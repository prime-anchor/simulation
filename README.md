# ①課題名
共同LPからの新規リードのバッティングチェック・振り分けアプリ

## ②課題内容（どんな作品か）
法人向け商材を販売するメーカーと、その商材を代理販売する代理店の「共同LP」を想定した、問い合わせの照合・振り分けアプリです。

### 共同LPと営業台帳について
共同LPは、代理店のWebサイトにメーカーの商材を掲載し、顧客からの問い合わせを受け付けるサービス紹介ページです。

今回想定する運用では、問い合わせ企業がメーカーの既存顧客であれば、メーカー側の担当者へ引き継ぎます。既存顧客とバッティングしなければ、代理店側でアプローチを進めます。

この確認に使う「営業台帳」は、メーカー側が用意する顧客・案件の一覧です。

### アプリの仕組み
- 「株式会社グー」「株式会社チョキ」「株式会社パー」の3社から、ランダムに1社をメーカーの既存顧客として営業台帳に登録します。
- LPを公開すると、新規企業、既存顧客、1件目と同じ企業の順に、3件の問い合わせが届きます。それぞれパートナーA・B・C経由の設定です。
- 問い合わせ企業を営業台帳と照合し、新規企業なら台帳へ登録、既存顧客なら担当者へ引き継ぎ、登録済み案件なら元の案件にまとめます。
- 新規登録した企業は台帳に追加され、後から届く問い合わせの照合にも反映されます。

### 操作方法
1. 「営業台帳を作る」を押して、既存顧客を登録します。
2. 「次へ：LPを公開する」で画面を切り替え、「LPを公開する」を押します。
3. 問い合わせが届いたら、「バッティングを確認する」を押します。
4. 照合結果に応じて有効になる操作ボタンを押し、台帳を更新します。
5. 3件の振り分けが終わったら、「もう一度試す」で最初から実行できます。

## ⑤工夫した点・こだわった点
- 配列とオブジェクトで営業台帳を管理し、企業名・既存顧客かどうか・経由パートナー・対応状況を記録しました。
- ifで「台帳に該当なし」「既存顧客」「新規登録済み」の3つに分岐し、照合結果に応じた操作だけを選べるようにしました。
- 1件目に登録した企業が、3件目には登録済みとして判定されるようにし、操作とデータを連動させました。
- setTimeout()で問い合わせの到着や照合に時間差を付け、jQueryの.fadeIn()で段階的に表示しました。
- .prop("disabled", true)で処理中の連打を防ぎ、console.log()で問い合わせ・照合・台帳更新を確認できるようにしました。
- LP公開時の色の変化やスタンプ、問い合わせ到着、照合バー、台帳更新時のハイライトで動きを加えました。
- 画面を切り替えた後も、上部に営業台帳を表示し、照合対象や更新内容を確認できるようにしました。

## ⑥難しかった点・次回トライしたいこと（又は機能）
- メーカーが用意した営業台帳をCSV等で取り込む機能に挑戦したいです。
- 問い合わせ履歴を一覧で確認できるようにしたいです。
